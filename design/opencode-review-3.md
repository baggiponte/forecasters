All eight are addressed.

## Remaining blockers to starting implementation

**None.**

These are small wording inconsistencies inside 0.3. Each is a one-line clarification and none forces a redesign:

- **How the adapter import string reaches the worker.** §3 says "The worker receives the adapter import string and options in an `init` message." §4 starts the worker with `--adapter <module:Class>` on argv. Pick one. The import string isn't secret, so either choice works.
- **`crash` and `timeout` kinds.** These are listed as wire `kind` values, but the parent detects them itself; the worker can't report them. Say they are generated by the parent.
- **Phase for an invalid-levels `WorkerError`.** §2.3 doesn't say which `phase` it gets. That decides whether it's terminal: `forecast` is non-terminal, `protocol` is terminal.
